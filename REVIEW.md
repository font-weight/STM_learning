## Обязательные условия выпуска

- **G1, электрическая безопасность:** пройдено по тексту и схемам соединений. Неизвестный стенд требует первичной проверки напряжений; raw-маршрут L07 её не отменяет.
- **G2, совместимость с целью:** пройдено по документации и коду. Не обнаружены неправомерные 128 Кбайт для C8, 32-битный TIM2, неподдерживаемый regular trigger или 5 В на ADC.
- **G3, полный путь инструментов:** пройдено как инструкция. CubeMX → CMake/GCC → build → flash/verify → breakpoint описан; реальное выполнение этого пути остаётся непроверенным.
- **G4, целостность concurrent data:** пройдено в пределах описанного учебного контракта и host-моделей. Ограничения DMA-истории, latency и времени владения явно названы; это не доказательство отсутствия всех аппаратных потерь.
- **G5, честность проверки:** пройдено. Host, модель HAL, static, ARM, браузер и физические испытания разделены.
- **G6, полнота поставки:** пройдено статически. Все 14 лабораторных и локальные цели ссылок присутствуют; runtime-навигация браузера отдельно не проверена.

## Что проверено независимо

Из свежей копии только файлов манифеста выполнена команда:

```sh
bash scripts/check_all.sh
```

Результат: exit code 0.

- Digital helpers: оптимизированная GCC-сборка и AddressSanitizer/UBSan.
- UART console с HAL-заглушкой: восстановление после повреждения RX/overflow/error, отказа rearm/abort, владение TX-буфером и восстановление прежнего PRIMASK.
- Host-buffering: свежая сборка; шесть контрактов отдельного эталона прошли. Начальный `student.c` **ожидаемо не прошёл** первый тест. Это учебный TODO-каркас, а не успешно реализованная очередь.
- CSV checker: 24 теста на синтетических данных.
- Модель прогресса: 11 тестов, включая интервалы D+1/3/7/21, пропущенные даты, экспорт/импорт и отклонение некорректного состояния.
- Markdown/compiler security: 17 тестов, включая небезопасные ссылки/HTML, данные внутри script, буквальный код и закрытые подсказки.
- Структура исходников: 14 модулей, зависимости, gates и 132 локальные ссылки/якоря.

Среда независимого запуска: Linux x86_64, GCC 14.2.0, Python 3.12.14, Node 24.19.0, GNU Make 4.4.1. LeakSanitizer отключён; проверки утечек не заявляются. Тесты не доказывают физическое происхождение CSV и не заменяют целевую сборку.

## Существенные исправления, повторно проверенные в этой версии

1. Единый владелец UART TX для ответов, метаданных и CSV; ограниченный pending-slot сохраняется при отказе принять передачу.
2. START/STOP явно добавляются в учебный parser с негативными host-тестами; смешанный лог отделяет session marker от обычного status-комментария.
3. Проверка ADC-прогресса отделена от 100-мс health bitmap: 300 мс на первый новый обработанный блок, затем 500 мс; tracking сбрасывается при каждом START.
4. Capture freshness проверяется в каждой итерации main; 150-мс внутренний timeout не смешивается с задержкой редкого UART-отчёта.
5. Есть функциональные маршруты без анализатора и без постоянного доступа к мультиметру в L07; неизмеренная точность остаётся явно непроверенной.
6. Доступ к мультиметру для первичного неизвестного стенда согласован с SAFETY. L05 требует L04 для полного UART-gate; карточки L05–L07 совпадают с лабораторными.
7. Native GCC/Clang, Bash, Make и Python отделены от Arm toolchain; Windows baseline не выдаёт пропущенный sanitizer run за успешный.
8. Подсказки details и сложные подписи ссылок безопасно обрабатываются renderer; поздние повторения нельзя выполнить четырьмя немедленными отметками.

## Первичные источники

Ключевые свойства сверялись непосредственно по [ST DS5319 Rev 20](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf), [RM0008 Rev 21](https://www.st.com/resource/en/reference_manual/rm0008-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf), [ES096 Rev 15](https://www.st.com/resource/en/errata_sheet/es096-stm32f101x8b-stm32f102x8b-and-stm32f103x8b-mediumdensity-device-limitations-stmicroelectronics.pdf) и [PM0056 Rev 7](https://www.st.com/resource/en/programming_manual/pm0056-stm32f10xxx20xxx21xxxl1xxxx-cortexm3-programming-manual-stmicroelectronics.pdf). В частности: C8 64 Кбайт/20 Кбайт; ADC до 14 МГц; допустимый TIM3_TRGO; APB timer doubling; ограничения PC13; ограничения overcapture flags и DMA/IRQ masking.

Текущий путь VS Code проверен по официальным [migration](https://dev.st.com/stm32cube-docs/stm32cubeide-vscode/latest/en/docs/markup/tutorials/migration.html) и [first project](https://dev.st.com/stm32cube-docs/stm32cubeide-vscode/latest/en/docs/markup/getting_started/first_project_creation.html): отдельный CubeCLT не является обязательным для архитектуры 3.x+. Наличие инструкции не означает выполненную установку. Для Windows дополнительно проверены [MSYS2 environments](https://www.msys2.org/docs/environments/) и официальные карточки пакетов.

## Оставшиеся проверки

1. Сгенерировать и собрать реальный STM32F103C8-проект по L00; сохранить версии, ELF/map и лог. Затем проверить интеграцию HAL-фрагментов на ARM.
2. Пройти аппаратные gates на конкретной проверенной плате, включая UART fault recovery, ADC/DMA timing, capture, watchdog и старт/останов.
3. Открыть финальный HTML в разрешённой браузерной среде и проверить реальные desktop/mobile сценарии, localStorage, импорт/экспорт, клавиатуру и печать. Файл browser_smoke.py пока означает только подготовленный тест.
4. Провести учебный прогон с одним учащимся и скорректировать оценки времени по реальным затруднениям.

Эти пункты являются границами доказательства, а не скрытыми выполненными этапами. При соблюдении этих ограничений комплект можно использовать как практический курс для собственного низковольтного стендового устройства.
