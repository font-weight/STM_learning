# Необязательная проверка файлов STM32F103C8/CB

Нужна, если хочется быстро исключить чужую цель, 128 КиБ вместо 64 КиБ или desktop ELF. Для выполнения L00 не обязательна. Требуется только Python 3.10+; зависимости не устанавливаются.

Скрипт **читает только указанные файлы**. Он не запускает CMake, GCC, код проекта, программатор, сеть или подключение к плате. Используйте свои доверенные локальные файлы. Результат относится к проверенным байтам с указанным SHA-256, а не к любому одноимённому файлу.

## Запуск из папки курса

Предположим, ваш сгенерированный проект находится рядом с папкой курса и называется `bluepill_bringup`. Замените пути на фактические: имя linker script смотрите в команде link, путь `.elf` — в успешном build-логе.

Только объявленная цель `.ioc`:

```sh
python3 tools/check_stm32_project.py --mcu STM32F103C8T6 --ioc "../bluepill_bringup/bluepill_bringup.ioc"
```

Цель и linker script:

```sh
python3 tools/check_stm32_project.py --mcu STM32F103C8T6 --ioc "../bluepill_bringup/bluepill_bringup.ioc" --linker "../bluepill_bringup/STM32F103C8TX_FLASH.ld"
```

После **своей настоящей ARM-сборки** добавьте образ:

```sh
python3 tools/check_stm32_project.py --mcu STM32F103C8T6 --ioc "../bluepill_bringup/bluepill_bringup.ioc" --linker "../bluepill_bringup/STM32F103C8TX_FLASH.ld" --elf "../bluepill_bringup/build/Debug/bluepill_bringup.elf"
```

На Windows используйте `py -3` или `python` вместо `python3`, если именно так запускается ваш Python 3.10+. Для **подтверждённого** STM32F103CBT6 укажите `--mcu STM32F103CBT6` и его файлы; это не способ обойти ошибку C8. Опция `--json` выводит тот же отчёт в JSON.

## Что означает каждая строка

| Статус | Значение | Следующее действие |
|---|---|---|
| `OK` | Конкретная проверка указанного файла прошла | Читать её область, не переносить результат на плату |
| `FAIL` | Файл противоречит выбранному учебному профилю или некорректен для проверки | Сверить точный МК, файл и первую причину; не увеличивать память C8 |
| `REVIEW` | Формат не поддержан достаточно уверенно | Проверить вручную; не переделывать корректный проект ради скрипта |
| `NOT RUN` | Файл/проверка не предоставлены или не входят в область скрипта | Оставить этот факт неподтверждённым |
| `INFO` | Записано значение из файла | Это инвентаризация, не доказательство установленной версии |

Коды завершения: `0` — выполненные проверки не выявили противоречий или неразобранного формата; `1` — есть `FAIL`; `2` — нужен ручной просмотр, если нет `FAIL`. Отсутствующий `.elf` остаётся `NOT RUN` даже при коде `0`. Общего «прошивка/плата PASS» скрипт не выдаёт.

## Точная область проверки

- `.ioc`: только явное поле `Mcu.CPN` с точной моделью C8/CB. Если генератор записал лишь диапазон в `Mcu.Name`, требуется ручная проверка в CubeMX. Частоты, пины, SWD и полнота generated init не проверяются.
- `.ld`: буквальные `ORIGIN`/`LENGTH` областей `FLASH` и `RAM`. Для C8: `0x08000000`, 65536 байт; SRAM: `0x20000000`, 20480 байт. Выражения, `INCLUDE` и дополнительные области требуют просмотра. Выбор именно этого linker script и правила размещения секций проверяются отдельно по link-команде/map.
- `.elf`: ELF32 little-endian ARM executable; доступность таблицы и байтов `PT_LOAD`; границы runtime- и load-областей; начальные SP/reset при расположении векторов в начале Flash; Thumb-бит reset и адрес в file-backed executable Flash. Образ с RAM-загрузкой, перенесёнными векторами или пользовательским bootloader находится **вне профиля L00** и может быть отклонён, даже если верен для другой задачи.

Первый SP может указывать ровно на верхнюю границу SRAM: стек растёт вниз. Это не ошибка «на один байт за памятью». Reset берётся из вектора, а не из поля entry ELF. Объём памяти подтверждает [DS5319](../docs/SOURCES.md#s1), назначение начальных векторов и Thumb-бита — [PM0056](../docs/SOURCES.md#s27).

**Что скрипт не доказывает:** что `.ioc`, linker script и ELF относятся к одному build; что в ELF инструкции именно Cortex-M3; что символы актуальны; что хватит стека; что Flash записана; что clock/pinout правильны; что кристалл подлинный; что проводка безопасна. Даже синтетический ELF-тест может пройти эти ограниченные проверки, поэтому они не являются удостоверением рабочего firmware.

## Как проверен сам checker

```sh
python3 -m unittest discover -s tests -p test_stm32_project_checker.py
```

Все тестовые IOC/linker/ELF-данные создаются в тестах и явно синтетические. Есть положительные случаи, границы памяти, C8/CB, неверная архитектура, перекрытие загрузочных диапазонов, отсутствие Thumb-бита, неверный стек, обрезанные файлы, отсутствие ELF и неоднозначные форматы. Это тесты парсера, не запуск CubeMX и не ARM-сборка.
