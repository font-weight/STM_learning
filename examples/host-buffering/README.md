# L10: очередь и CSV на обычном компьютере

Это **учебный каркас**, а не готовая библиотека. `student.c` намеренно содержит TODO. Первоначально `make build` должен собираться, а `make check` должен сообщать FAIL. Красный тест до реализации — ожидаемая исходная точка, не пройденная проверка алгоритма.

Нужны установленный **native** C11-компилятор (GCC или Clang) и GNU Make; Arm `arm-none-eabi-gcc` не создаёт исполняемый файл для ПК. Выбери host-маршрут в [TOOLCHAIN](../../docs/TOOLCHAIN.md). Никаких STM32, HAL, Python-пакетов, доступа к USB, сети или плате эти команды не используют.

```sh
make build
make test-list
./build/test_stream initial_empty
```

Реализуй по очереди `record_queue_init`, `record_queue_push`, `record_queue_pop`, `stream_format_csv`. Контракт находится в `stream.h`. После каждого небольшого изменения запускай отдельный тест. Затем:

```sh
make check
make sanitize
```

Sanitizers необязательны: они должны поддерживаться твоим host-компилятором/ОС. Их отсутствие не означает, что память проверена. Обычные тесты обязательны.

## Что тестируется

1. Инициализация даже после ненулевого содержимого памяти; пустое чтение не меняет результат
2. FIFO и полнота всей записи; drop-newest сохраняет уже накопленные записи
3. Многократный переход head/tail через конец массива
4. Насыщение счётчика rejected на UINT32_MAX
5. Точная десятипольная CSV-строка, CRLF, длина без завершающего NUL
6. Нулевой и маленький буфер, предохранители вокруг него, worst-case 111 байт текста плюс NUL

Добавь собственный тест **до** исправления намеренно внесённой ошибки. Предложение: потерянная запись после чередования push/pop при занятом буфере.

## Чего тесты не доказывают

- Эта очередь рассчитана на один контекст исполнения. Она не потокобезопасна и не ISR-safe
- Host-тест не моделирует порядок памяти, DMA, периферию, timing, ISR latency или UART
- Форматтер принимает любые uint32_t для проверки границ; осмысленность ADC/частоты/valid проверяется отдельно
- Размер структуры/size_t на host может отличаться от Cortex-M3. RAM-бюджет берётся из целевой сборки и map-файла
- Отсутствие падения под sanitizers не является доказательством отсутствия всех дефектов

Для L10 очередь сводок обслуживает **только main**: main получает независимый ADC mailbox, считает статистику, кладёт record; main отправляет его UART. Не вызывай эти функции из ISR без отдельного проекта синхронизации. UART DMA использует отдельный стабильный TX-буфер до callback; сама очередь это правило не обеспечивает.

## Не открывай готовое решение вместо попытки

Основной файл `student.c` не содержит готового решения. Отдельный [эталон](reference/README.md) существует для проверки тестов и позднего сравнения; не открывай его до собственной попытки. Сначала запиши инварианты и вычисли поведение вручную для ёмкости 2. AI можно попросить объяснить один падающий тест или проверить конкретный diff; нельзя считать работу освоенной, пока не повторишь очередь из памяти без него.

Вернуться к [L10](../../docs/labs/10-buffering-storage.md).

## Разделение проверок релиза и задания

Из этой папки:

```sh
make release-check
```

Ожидаемый exit code: **0** для исходного учебного пакета. Команда собирает starter и отдельный opt-in oracle, проверяет все шесть контрактов на oracle и отдельно подтверждает точный ожидаемый RED начального starter. Она не объявляет TODO-реализацию пройденной и не проверяет плату. Требует Python 3 для небольшого runner.

```sh
make exercise-check
```

Это проверка **твоего `student.c`**, тот же смысл, что `make check`. У исходного starter: исполняемый тест возвращает 1, GNU Make обычно возвращает 2, сообщение `Test failed: initial_empty`. После твоей реализации ожидается exit code 0 и шесть PASS.

После изменения `student.c` пользуйся `exercise-check`, а не проверкой исходного RED-релиза. Не скрывай его неуспешный результат через `|| true` и не записывай «все тесты пройдены», когда запускался только oracle.

Sanitizers для oracle можно отдельно проверить командой:

```sh
make IMPL=reference/stream_reference.c BUILD_DIR=build-reference-sanitize CFLAGS="-std=c11 -O1 -g -Wall -Wextra -Werror -Wpedantic -fsanitize=address,undefined -fno-omit-frame-pointer" check
```

На редакционной машине LeakSanitizer не работал из-за ограничения ptrace. AddressSanitizer+UBSan отдельно прошли с `ASAN_OPTIONS=detect_leaks=0`; проверки утечек этим не заявляются. В этом модуле нет динамических выделений памяти.
