# Проверки цифровой части

Из корня репозитория:

```bash
bash tests/run_digital_tests.sh
```

Нужны Bash и C11-совместимый GCC. Скрипт собирает во временную папку и удаляет её при выходе. Альтернативный компилятор: `CC=clang bash tests/run_digital_tests.sh`. Только обычный прогон: `SANITIZE=0 bash tests/run_digital_tests.sh`.

## Фактически выполнено 2026-10-09

- GCC Debian 14.2.0, `-std=c11 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror -O2`: PASS
- Те же тесты с AddressSanitizer и UndefinedBehaviorSanitizer: PASS
- LeakSanitizer выключен по умолчанию через `detect_leaks=0`, поскольку окружение запуска использует ptrace; код не выделяет heap
- `bash -n` для script: PASS
- Проверка закрытия Markdown fences и существования локальных ссылок цифровых документов: PASS

## Pure-C helpers

`test_digital_helpers.c` проверяет:

- Вычитание tick через UINT32_MAX, точные границы deadline, нулевой/недопустимый период, пропущенные слоты и сохранение фазы
- Debounce с дребезгом, удержанием, отпусканием, нажатой кнопкой при старте, rollover и нулевым порогом
- FIFO full/empty, сохранение порядка, 1000 циклов заполнения/освобождения с оборачиванием индексов, охранные слова вокруг буфера
- Строгую грамматику, диапазоны, отрицательные/слишком большие числа, UINT32 overflow, пробелы/суффиксы/NUL, вход без terminating NUL
- CR/LF/CRLF, точную границу 47/48 байт, drop-until-EOL и восстановление после ошибки
- 200000 детерминированных псевдослучайных входных байт и сохранение границ памяти
- Capture modulo 65536, все начальные значения 16-битной отметки для периода 1000
- PWM 0/50/100%, все целые проценты, отказ при неверных параметрах
- Health bitmap: очистку и после успешного, и после неуспешного окна; запрещённый пустой required mask

## UART transport с имитацией HAL

`test_uart_console_mock.c` компилирует настоящий учебный `uart_console.c` с маленьким **host-only test double** из `tests/mocks/main.h`. Это дополнительно проверяет:

- Приём и dispatch корректной команды
- Забывание уже разобранного префикса после full FIFO
- Переполнение ровно на CR/LF не отбрасывает следующую целую команду
- Сброс неопределённого хвоста после HAL error
- Восстановление после ошибки повторного arm и после неудачного abort
- Копирование ответа в собственный TX buffer, busy/drop, границу 127/128 байт и failed start
- Восстановление прежнего PRIMASK вместо безусловного разрешения IRQ

Mock не моделирует USART registers, NVIC timing, атомарность реального interrupt entry, HAL всех версий, ARM-инструкции или электрическую линию. Не копируй `tests/mocks/main.h` в CubeMX-проект.

## Не выполнялось

- Компиляция/link generated STM32 firmware ARM toolchain
- Прошивка и debugger на физической Blue Pill
- Измерения GPIO/PWM/capture/UART
- Reset от физического IWDG, debug freeze и проверка option bytes

В отчёте учащегося нужны отдельные строки «host tests», «target build» и «hardware». PASS первой строки не заполняет две остальные.

## Дополнения к цифровой части, 2026-10-09

Команды из корня курса:

```bash
bash tests/run_digital_tests.sh
python3 tests/check_digital_transfers.py
bash -n tests/run_digital_tests.sh examples/digital/transfer-guard/run_tests.sh
```

Дополнительно нужны Python 3.10+ для проверки учебного фрагмента и mutation-контроля. Обычная C-регрессия по-прежнему требует только Bash и C11-компилятор. В этом окружении фактически выполнены GCC 14.2.0 и Python 3; Clang не установлен и его прогон не заявлен.

- `test_time` теперь включает конкретную частично заполненную трассу L03: `0xFFFFFFF0 → 0x10`, период 25 ms, anchor=9, следующий слот в `0x22`, а также изменённый now=`0x42`
- UART mock дополнительно проверяет все места разрыва `PERIOD 250` между вызовами poll, отсутствие dispatch до CR/LF, единственный dispatch на CRLF и предел 32 байта за один poll
- [L11 transfer guard](../examples/digital/transfer-guard/README.md): reference проходит **121 проверку в 9 сценариях**, обычный запуск и ASan/UBSan. В общий runner входит только reference
- `check_digital_transfers.py` извлекает и компилирует **реальный C-блок из L06**, не его вручную переписанную копию. Проверены sequence=0 при wrap, invalid startup/первый фронт, точная граница 150 ms и короткий интервал через tick wrap
- Отдельный negative control показывает, что timestamp после полного 2^32-ms молчания неотличим от нового по младшим битам. Этот случай прямо исключён временным договором L06; тест не доказывает корректность многонедельного автономного измерителя
- Те же guard-тесты отвергают **12 компилируемых мутаций**: сложение deadline, ошибка `>`/`>=`, повтор или старый sequence как прогресс, игнорирование validity, старое состояние после START, renewal от START, самовосстановление после expiry, зашитые бюджеты, отсутствие deadline-проверки в accept, старая baseline и aging в STOPPED. Все должны завершаться логическим отказом тестов, а не ошибкой компиляции
- `bash -n` обоих скриптов: PASS

Отдельный запуск начальной ученической заготовки:

```bash
bash examples/digital/transfer-guard/run_tests.sh --student
```

Зафиксирован ожидаемый exit 1: **82 из 121 проверок не проходят**. Заготовка компилируется с `-Werror`; это намеренный учебный исход, а не пропущенная ошибка reference. Ученик меняет `student.c`; эталонный PASS не считается его самостоятельным результатом.

Не выполнялись ARM/HAL target build, прошивка, GPIO/PWM/capture/UART на плате, физический IWDG или браузерная проверка. Новые host-тесты не меняют эти статусы.


## Регрессия первого перехода L00 → L01 → L02

```bash
python3 tests/check_digital_startup.py
```

Это проверка материалов на host с GCC-совместимым compiler, GNU-совместимым linker `--gc-sections` и `nm`, не новая обязательная установка ученику. Она извлекает реальные C-блоки L01, проверяет варианты PC13 active-low и PB0 active-high в маленьком native mock, а затем сравнивает символы двух сборок: с `(void)probe_data;` объект остаётся в `.data`, без этой строки контрольный неиспользуемый volatile-объект удаляется. Проверяется также арифметика BSRR-масок; электрические побочные эффекты регистра не моделируются.

Выполнено GCC 14.2.0 на Linux: оба LED-варианта и обе linker-пары PASS. Это не ARM startup/link и не target build. Реальные `.map`, прошивка/Verify и физический световой рисунок всё равно проверяются учеником.

`check_digital_transfers.py` дополнительно оставляет имя `now` занятым, как в L04, перед вставкой настоящего L06-блока: повторное объявление стало бы ошибкой компиляции. Проверяются сохранённые `capture_result_valid`/`capture_frequency_millihz` и обнуление числа при недостоверном результате; ноль не заменяет отдельный validity-флаг.
