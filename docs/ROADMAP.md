# Практический маршрут STM32F103

Этот курс рассчитан на человека, который уже писал программы для Arduino и AVR. Результат: самостоятельно собрать небольшой низковольтный прибор, объяснить его ограничения и доказать, что он работает после сбоя и изменения требований.

Курс идёт от инженерных задач: отличить неисправный вход от ошибки программы, совместить измерение и консоль, увидеть потерю данных, восстановиться после сбоя. Теория появляется перед действием и обычно занимает 5–10 минут. Для нового механизма есть разобранный пример, для знакомого — короткий путь к самостоятельной проверке. Отметка «прочитал» не заменяет измерение.

Учиться здесь означает всё реже нуждаться в готовом ходе решения. Сначала объясни, почему работает один пример, затем восстанови пропущенный шаг, потом измени условие без рецепта. Это выбор опоры для конкретного навыка, а не обязанность трижды писать каждый проект. Обоснование и ограничения подхода — в [методах обучения](learning-methods.md).

## С чего начать

1. Пройди [первый запуск](START_HERE.md) и [L00](labs/00-bringup.md).
2. В [ASSESSMENT](ASSESSMENT.md) выбери входную задачу для навыка, чьё пошаговое упражнение хочешь пропустить. Необязательно сдавать все семь задач до L01.
3. Выбери ближайшую лабораторную, для которой выполнены зависимости. На каждом шаге сохраняй один небольшой работающий проект и результат проверки.
4. Постепенно превращай его в [стендовый регистратор](CAPSTONE.md): аналоговый вход, измерение частоты, команды и запись на компьютер.

Обычный маршрут занимает примерно **48 часов** практики. С внешней I2C-периферией и двумя дополнительными задачами получится примерно **58 часов**. Это ориентиры с отладкой и короткими повторениями, а не обещание скорости. Установка инструментов, доставка деталей и поиск неисправности самой платы могут увеличить время.

Ускоренный маршрут сокращает знакомые упражнения, сохраняя STM32-специфичные проверки. Не проходи debounce заново, если можешь показать корректную реализацию, объяснить ошибку и выдержать новое условие. Сколько времени это сэкономит, станет понятно после L04; заранее обещать одинаковое ускорение людям с разным опытом нельзя.

## Оснащение и честные замены

| Для чего | Основной вариант | Допустимая замена и её предел |
|---|---|---|
| Контроллер | Blue Pill с проверенной маркировкой STM32F103C8/CB | Другая F103-плата после сверки корпуса и pinmap; чужой клон MCU не считается автоматически эквивалентным |
| Прошивка и отладка | SWD-пробник класса ST-LINK, провода GND/SWDIO/SWCLK; NRST полезен | UART ROM-загрузчик позволяет прошить, но не выполняет gate отладчика |
| Питание | Один проверенный источник согласно [SAFETY](SAFETY.md) | USB-разъём платы может быть источником питания; это не означает наличие USB-загрузчика или USB-UART |
| Консоль и CSV | USB-UART с логическими уровнями 3,3 В; TX/RX/GND | Виртуальный COM встроенного пробника, если он действительно есть и подключён; обычный SWD сам по себе UART не заменяет |
| Кнопка и проводка | Макетная плата, кнопка, перемычки, резисторы 1 кОм и 10 кОм | Перемычка PB12→GND заменяет кнопку; исходный уровень должен быть определён pull-up |
| Аналоговый сигнал | Потенциометр около 10 кОм между 3V3 и GND; движок через 1 кОм к PA0 | PA0 через 1 кОм поочерёдно к GND и 3V3 проверяет два уровня. Переставляй провод при выключенном питании. Такая проверка не доказывает точность в вольтах |
| Первичная проверка питания и уровней | Доступ к мультиметру; можно взять взаймы | Для неизвестной платы, пробника и адаптера первичная проверка по SAFETY обязательна. Позже L07 можно пройти по raw-маршруту без постоянно доступного прибора, если безопасное питание уже проверено |
| Частота и PWM | Перемычка PA1→1 кОм→PA8 | Второй известный генератор 0–3,3 В с общей землёй даёт более независимую проверку |
| Наблюдение времени | Логический анализатор или осциллограф | Loopback через capture и аппаратные счётчики позволяют пройти функциональные проверки; абсолютная точность времени остаётся непроверенной |
| Внешняя периферия | Выбранный 3,3-вольтовый I2C-модуль | Не нужен для core: обязательный SPI loopback использует перемычку MOSI→MISO |

Не покупай датчики, дисплеи, SD-модуль или RTOS-отладчик заранее. Для обязательного курса они не нужны. Полный минимум для итогового стендового проекта: плата, отладчик, консоль, источник питания, перемычки, простые пассивные компоненты и доступ к мультиметру для первичной проверки неизвестного стенда. Его можно взять взаймы. Сокращённый raw-маршрут L07 без мультиметра разрешён после этой проверки; он не отменяет измерение безопасных уровней перед подключением сигналов. Потенциометр и доступный во время L07 мультиметр позволяют дополнительно проверить промежуточные уровни и оценить точность.

## Общая конфигурация

Базовый курс использует исходный STM32CubeMX с пакетом STM32CubeF1/HAL1 и VS Code. Подробные команды и версии записывай по [TOOLCHAIN](TOOLCHAIN.md).

Первый рабочий профиль: HSI 8 МГц, PLL выключен; SYSCLK, HCLK, PCLK1 и PCLK2 номинально 8 МГц; делители APB равны 1; ADC clock 4 МГц. Так внешний кварц неизвестной платы не блокирует обучение. Более высокая частота является отдельным изменением с повторной приёмкой, а не обязательной настройкой «как у всех».

| Ресурс | Назначение |
|---|---|
| PA0, ADC1_IN0 | Аналоговый вход |
| TIM3 TRGO | Период запуска ADC |
| PA1, TIM2_CH2 | Низковольтный тестовый PWM |
| PA8, TIM1_CH1 | Вход измерения периода |
| PA9 / PA10, USART1 | TX / RX консоли |
| PB12 | Кнопка с pull-up |
| PC13 | Светодиод только после проверки разводки и полярности конкретной платы |
| PA13 / PA14 | SWD; сохраняем для отладки |
| PA5 / PA6 / PA7 | SPI1 SCK / MISO / MOSI в L09 |
| PB6 / PB7 | I2C1 SCL / SDA в дополнительном упражнении |

Распиновка функций, память MCU и электрические пределы сверяются по [официальному datasheet STM32F103x8/xB](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf). Для C8 бюджетируй 64 Кбайт Flash и 20 Кбайт SRAM; не полагайся на неподтверждённую «скрытую» Flash. Blue Pill является названием платы, а не гарантией её схемы или подлинности микроконтроллера.

## Четыре работающих результата

| Этап | Задача, ради которой нужны лабораторные | Что сохраняешь |
|---|---|---|
| L00–L04: управляемый прибор | Кнопка и команды остаются отзывчивыми, даже когда несколько действий идут одновременно | Воспроизводимый build и короткий сценарий неправильного ввода |
| L05–L09: измерения с пределами | Генератор и входы дают осмысленные числа; пропавший сигнал отличается от настоящего нуля | Расчёт, реальное наблюдение и границы вывода |
| L10–L11: наблюдаемые потери | При перегрузке прибор сообщает, что потерял, и возвращается в управляемое состояние | Один нормальный лог и один объяснённый отказ |
| L12–L13: передача другому человеку | Прибор можно собрать, запустить и проверить по оставленной инструкции | Исходный CSV, приёмка и самостоятельное изменение требования |

Один проект постепенно обрастает возможностями; не нужно оформлять четырнадцать отдельных отчётов. Рабочие версии удобно сохранять коммитами. Один лог или тест может подтверждать сразу несколько пунктов, если понятно, что именно он проверяет.

Выбери личный вопрос для итогового стенда: «видно ли изменение аналогового уровня?», «когда исчезает частотный сигнал?» или «где заканчивается пропускная способность?». Это меняет акцент наблюдений, а не обязательный контракт и не список покупок. Новые датчики и интерфейсы оставь до приёмки базового прибора.

## Зависимости без лишних ожиданий

Основная цепочка: L00 → L01 → L02 → L03 → L04. Затем можно чередовать два направления:

- Таймеры: L05 → L06. Полный gate L05 включает UART-команды и поэтому требует L04; автономный PWM можно исследовать уже после L03
- Измерения: L07; после L05 и L07 — L08 → L10 → L11

L09 начинается после L04 и не требует законченной аналоговой части. L12 соединяет L06, L08, L10 и L11. L13 проверяет сборку целиком. Нельзя компенсировать неработающий базовый навык чтением последующих страниц.

## Одна сессия на 60–90 минут

Начни с одного законченного действия: «доказать, почему пропадает строка», а не «изучать DMA». Пример распределения 75 минут:

- **5–10 минут:** восстановить прошлое решение или расчёт, не открывая старый ответ; затем свериться.
- **5–10 минут:** выбрать прогноз для сегодняшней задачи и прочитать только недостающую теорию.
- **40–50 минут:** реализовать, измерить, разобраться с одним расхождением. Если причина неизвестна, сначала различающий эксперимент, потом исправление.
- **5–10 минут:** сохранить доказательство, назвать непроверенное и оставить следующий маленький шаг.

Не надо в каждой сессии обязательно и ломать, и восстанавливать, и переносить. Эти действия распределены по лабораторной. Уже найденная настоящая ошибка может заменить учебную, если ты доказал её причину и проверил исправление. Не воспроизводи опасные электрические ошибки ради тренировки.

Если 15–20 минут ты только перебираешь настройки и не получаешь нового наблюдения, используй [одну подсказку](AI_WORKFLOW.md) или [систематическую отладку](DEBUGGING.md). Не превращай самостоятельность в требование угадывать неизвестное API.

Около пяти 75-минутных сессий в неделю дают примерно восемь недель для 48 часов core, без обещания уложиться в них при проблемах с инструментами. Короткие возвраты к материалу входят в эти сессии; установка, доставка деталей и длительный ремонт стенда могут требовать отдельного времени.

## Как не забыть и не утонуть в повторениях

На сайте предложены возвраты примерно через **1, 3, 7 и 21 день** после первой приёмки. Это удобные напоминания, а не доказанный оптимум для STM32. Подстраивай их под расписание и результат: после затруднения вернись на следующей сессии; после уверенного решения используй более поздний возврат. Пропущенную дату не нужно компенсировать четырьмя одинаковыми попытками подряд.

В начале сессии достаточно одной задачи на 5–10 минут. При нескольких просроченных темах начни с той, которая нужна сегодня или уже дала ошибку. Проверяй решение, а не запоминание имён HAL-функций: восстанови владение буфером, выбери расчёт таймера, отличи два источника потери. Документация разрешена после первой версии из памяти; отметь, чем пришлось воспользоваться.

Когда отдельные механизмы уже понятны, смешивай похожие ситуации: изменился clock таймера или его PSC? ADC выдаёт больше отсчётов или UART передаёт меньше строк? Пропал входной сигнал или переполнилась очередь? Сначала нужно выбрать подходящую модель, а не просто подставить числа в формулу из заголовка. Для этого есть [смешанные задачи](ASSESSMENT.md#смешанные-задачи-для-короткого-возврата).

Не начинай одновременно незнакомые DMA, I2C и watchdog ради «чередования»: сначала получи короткий рабочий путь для каждого. Условия перехода и отсроченной проверки описаны в [ASSESSMENT](ASSESSMENT.md).

## Что считается базой, а что отложено

В core есть GPIO и регистровая грамотность, clock tree, EXTI/NVIC, таймеры, PWM, input capture, UART, ADC, DMA, SPI, ошибки I2C на уровне модели обмена, ограниченные буферы, watchdog, память и воспроизводимая сборка. HAL используется как рабочий инструмент; важно уметь проследить конкретную настройку до регистра, а не переписывать HAL целиком.

После core выбирай только расширение, нужное собственному прибору:

- **I2C, +2 ч:** прочитать идентификатор и регистр выбранного 3,3-вольтового устройства, обработать отсутствие ACK и timeout.
- **SPI-накопитель, около +4 ч:** заменить host CSV на SD/другой накопитель; изучить реальные уровни модуля, задержки записи, целостность и отказ питания. Это дополнительный проект, а не обещанный универсальный драйвер любого модуля.
- **Регистровый перенос, около +4 ч:** один уже проверенный GPIO/таймерный путь реализовать через CMSIS/регистры и сравнить поведение. Основная регистровая грамотность к этому моменту уже пройдена.

RTC и low-power нужны для автономного прибора на батарее; USB — для собственного USB-интерфейса; CAN — для отдельной защищённой сети с трансивером; RTOS — когда измеренная сложность задач оправдывает планировщик. Они сознательно не входят в первый прибор. У STM32F103C8 нет аппаратного DAC: задача аналогового выхода потребует другой подход или внешнюю микросхему.

Этот курс не является проверкой электромагнитной совместимости, электрической безопасности или готовности к серийному производству. Для автомобильного мотор-тестера далее понадобятся отдельный входной тракт, защита, диапазоны, изоляция при необходимости и независимые испытания. Итоговый стенд к автомобилю, зажиганию и силовым цепям не подключается.
