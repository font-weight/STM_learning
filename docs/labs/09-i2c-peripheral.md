# L09. SPI и I2C: подключить незнакомую периферию

**Обязательная часть:** SPI loopback, около 1 часа; достаточно проводов, без покупки модуля.  
**Расширение:** I2C-датчик, около 2 часов; отсутствие датчика не блокирует курс.  
**Результат:** настроить физический интерфейс, прочитать временную диаграмму, различить успешную транзакцию и осмысленные данные.  
**До начала:** GPIO, UART из [L04](04-uart-protocol.md) и ограниченные timeouts. L08 не является prerequisite: шины можно изучить до ADC/DMA.

> Отдельная копия проекта: ADC/DMA и таймеры пока выключены, чтобы исследовать шину без фоновых эффектов. Часы остаются HSI 8 МГц, AHB/APB1/APB2 /1. Общая земля обязательна. Все сигналы и подтяжки в этой работе только 3,3 В. Перекоммутация при выключенном питании. Не подключать одновременно два push-pull выхода друг к другу.

## 1. Миссия: отличить обмен от доказательства

В трёх пробных запусках получены: A — `HAL_OK`, RX совпадает с TX; B — `HAL_OK`, RX весь нулевой; C — `HAL_TIMEOUT`, в RX остался прошлый правильный ответ. До включения выбери, какие результаты можно считать новым успешным обменом, и назначь каждому один следующий тест. Эти условия придуманы для разбора, не сняты с платы.

<details>
<summary>Обратная связь после своего решения</summary>

A подтверждает совпадение в этом loopback; ещё нужен меняющийся вектор и повторение. B показывает, что master завершил тактирование, но данных ожидаемого вида нет: проверь провод/вход. C нельзя выдавать за новый ответ, каким бы правдоподобным ни был старый буфер. Ни один из трёх исходов не подтверждает совместимость с неизвестным датчиком.

</details>

Если у тебя уже есть самостоятельный SPI-драйвер, выполни 1000 обменов, опыт с разрывом и перенос §7 без фрагмента кода. Этими доказательствами можно заменить пошаговый разбор. I2C остаётся отдельным необязательным маршрутом.

**SPI:** master выдаёт clock, с каждым переданным битом одновременно принимается бит. Устройство выбирается отдельным CS. CPOL определяет уровень clock в покое, CPHA — фронт выборки относительно начала такта. Размер слова, порядок битов, максимальная частота и паузы CS берутся из даташита устройства.

**I2C:** SDA/SCL работают с открытым стоком и подтяжками. Адрес шины, адрес регистра и данные — разные сущности. ACK означает ответ на конкретный этап, но ещё не подтверждает, что это нужный датчик или корректное измерение.

Прочитай только соответствующие рисунки timing и описание регистров интерфейса в [RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf). Не читай всю тысячу страниц перед первым экспериментом.

## 2. SPI без внешнего устройства: точная конфигурация

| CubeMX | Значение |
|---|---|
| SPI1 mode | Full-Duplex Master |
| PA5 / PA6 / PA7 | SCK / MISO / MOSI, без remap |
| Data size / first bit | 8 bit / MSB first |
| CPOL / CPHA | Low / 1 Edge, то есть mode 0 |
| Baud prescaler | 32: PCLK2 8 МГц /32 = 250 кГц |
| NSS | Software |
| TI mode / CRC | Disabled / Disabled |
| PA4 | GPIO output push-pull, label `SPI_CS`, initial High |
| DMA / SPI IRQ | Disabled: начинаем с blocking transfer |
| USART1 | 9600 8N1; достаточно короткого итога раз в секунду |

Если твоя копия уже настроена на 115200, можно оставить её, но терминал должен совпадать. PA5/PA7 — alternate-function push-pull, PA6 — input. PA4 служит обычным GPIO, а не аппаратным NSS. Не remap SPI1 на PB3/PB4/PB5: он здесь не нужен, а SWD сохраняем.

**Провод:** PA7 (MOSI) через 1 кОм к PA6 (MISO). PA5 к MISO не подключать. PA4 можно подключить только к входу анализатора. Дополнительный 10 кОм от PA6 к GND поможет сделать опыт с разрывом loopback воспроизводимым; он не обязателен для нормального loopback.

Для анализатора: GND к GND платы, входы к PA4/PA5/PA7/PA6, допустимые уровни входов проверить. Анализатор не должен питать сигнальные линии платы. Без него проверишь байты и статусы, но не заявляй, что измерил setup/hold или качество фронтов.

## 3. SPI: маленькие задачи

### 3.1. Предскажи байты и длительность

Возьми тестовый вектор `00 FF AA 55 01 80 3C C3`. Почему одних нулей недостаточно? Сколько SCK-периодов требуется для восьми байтов? Какова идеальная длительность clock-части при 250 кГц? Отдельно учти программные паузы между словами.

Создай свои `tx` и `rx`, обнули счётчики успешных `transfers`, несовпадений `mismatches`, ошибок `spi_errors`. Перед вызовом заполняй каждый `rx[i]` значением, отличным от ожидаемого `tx[i]`, например `tx[i] ^ 0xFFU`. Так пропущенная операция не прячется за старым правильным буфером. Сравнение данных выполняй только после `HAL_OK`.

### 3.2. Выполни одну транзакцию

После собственной попытки можно сверить узкий опорный фрагмент. В `USER CODE BEGIN Includes` добавь `#include <stddef.h>` для `size_t` и `#include <stdint.h>` для `uint8_t`. Данные живут до возврата blocking-вызова; код расположен в `main`, не в ISR.

```c
uint8_t tx[] = {0x00, 0xFF, 0xAA, 0x55, 0x01, 0x80, 0x3C, 0xC3};
uint8_t rx[sizeof tx] = {0};
/* Repeat this preparation before each new transfer attempt. */
for (size_t i = 0U; i < sizeof rx; ++i) {
    rx[i] = (uint8_t)(tx[i] ^ 0xFFU);
}
HAL_GPIO_WritePin(SPI_CS_GPIO_Port, SPI_CS_Pin, GPIO_PIN_RESET);
HAL_StatusTypeDef status = HAL_SPI_TransmitReceive(
    &hspi1, tx, rx, (uint16_t)sizeof tx, 20U);
HAL_GPIO_WritePin(SPI_CS_GPIO_Port, SPI_CS_Pin, GPIO_PIN_SET);
```

После `HAL_OK` сравни каждый принятый байт с переданным. При другой ошибке не публикуй `rx` как успешный ответ; сохрани status и `HAL_SPI_GetError(&hspi1)`. Перед повтором после ошибки проверь состояние интерфейса; не запускай бесконечные повторы без паузы. У этой blocking-функции окончание транзакции и обработка флагов находятся в [официальном SPI HAL F1](https://github.com/STMicroelectronics/stm32f1xx-hal-driver/blob/master/Src/stm32f1xx_hal_spi.c).

PA4 не подключён к принимающему устройству, поэтому этот loopback не проверяет реакцию slave на CS. Он только позволяет наблюдать выбранные границы твоей транзакции. Нельзя объявлять датчик исправным на основании loopback.

### 3.3. Сделай результат проверяемым

Повтори 1000 транзакций с паузой 1 мс между ними, без печати внутри каждой. Меняй один байт счётчиком, чтобы отличать новый ответ от старого. Выведи итог. При нормальном loopback ожидаются 1000 успешных транзакций, нулевые mismatches и нулевые ошибки HAL.

Если есть анализатор, сохрани один кадр:

- SCK в покое low; декодер mode 0, MSB first, 8 bit
- 64 такта для восьми байтов; период SCK около 4 мкс при номинальном HSI
- Переданные/принятые байты совпадают; CS охватывает транзакцию
- Идеальная clock-часть 256 мкс, но суммарный кадр может быть дольше из-за пауз HAL/CPU

### 3.4. Безопасная поломка

Выключи питание и убери перемычку MOSI→MISO. При дополнительной подтяжке MISO к GND приём обычно станет нулевым; без неё уровень может плавать. После включения отличай `HAL_OK` от совпадения данных: master может успешно тактировать в пустоту, SPI не имеет обязательного ACK.

Восстанови перемычку и повтори 1000 транзакций. Отдельно поменяй prescaler 32→64. До запуска допиши: SCK=___, период=___, 64 такта=___. С анализатором сравни отношение длительностей clock-части: широкий диагностический ориентир 1,9…2,1. Это учебный допуск для поиска грубой ошибки, не допуск HSI или интерфейса. Без анализатора проверь новые настройки и целостность байтов, а фактическое время отметь непроверенным.

<details>
<summary>Сверка расчёта после собственного ответа</summary>

Номинально 125 кГц, 8 мкс и 512 мкс вместо 250 кГц, 4 мкс и 256 мкс. Сравнивай сумму clock-периодов или участок без программных пауз. Длительность всего HAL-вызова не обязана удвоиться: постоянные программные расходы остались.

</details>

**Важная ловушка:** переключение CPOL/CPHA одновременно у передатчика и приёмника одного SPI loopback может оставить сравнение успешным. Это не доказательство совместимости режима с внешним slave. Для проверки его режима нужен даташит и/или независимый приёмник/декодер.

## 5. Дополнение I2C: пример с LIS3DH

Задача — самостоятельно подключить документированную периферию. Здесь конкретный учебный пример — **LIS3DH на breakout с проверенной совместимостью 3,3 В**. Надпись на похожем модуле или идентичный разъём не заменяют его схему. Не переноси адреса/регистры на MPU6050, BME280 и другие устройства.

У самого LIS3DH питание/уровни и выводы описаны в [официальном даташите](https://www.st.com/resource/en/datasheet/lis3dh.pdf). Проверь модуль: куда ведёт VCC, есть ли регулятор, к чему подключены pull-up, где VDD_IO, CS и SA0. Если схемы нет и уровни неясны, не подключай модуль к MCU.

### 5.1. Схема

| Blue Pill | LIS3DH breakout |
|---|---|
| 3V3 | Проверенный вход питания 3,3 В / VDD; VDD_IO тоже 3,3 В |
| GND | GND |
| PB6 | SCL |
| PB7 | SDA |
| 3V3 | CS: high выбирает I2C |
| GND | SDO/SA0: адрес 0x18 |

Для SA0 high адрес 0x19. Страп менять при выключенном питании. На SDA и SCL нужны внешние подтяжки к **3,3 В**, например по 4,7 кОм для коротких проводов. Сначала проверь уже установленные на модуле: параллельное соединение уменьшает эквивалентное сопротивление. Внутренние слабые GPIO pull-up не считаем полноценной заменой.

Обесточь обе стороны при перестановке проводов, чтобы не питать выключенный модуль через сигналы. Не используй модуль, который подтягивает SDA/SCL к 5 В, без правильно спроектированного согласования; в этой работе такого согласования нет.

### 5.2. CubeMX

- I2C1, PB6 SCL / PB7 SDA, без remap
- GPIO alternate-function open-drain; внешние подтяжки
- Speed **80 000 Гц**, Standard mode; duty cycle 2
- Addressing mode 7 bit; own address 0; dual address и general call disabled
- `NoStretchMode = I2C_NOSTRETCH_DISABLE`
- Blocking API, без I2C/DMA IRQ на первом шаге
- PCLK1 = 8 МГц

80 кГц выбраны намеренно: ES096 §2.8.5 описывает ограничения repeated START около 88–100 кГц при некоторых условиях фронта/clock stretching. Это не утверждение, что 100 кГц всегда не работает. Подробности других ограничений F1 сверяй по ревизии кристалла в [ES096](https://www.st.com/resource/en/errata_sheet/es096-stm32f101x8b-stm32f102x8b-and-stm32f103x8b-mediumdensity-device-limitations-stmicroelectronics.pdf).

### 5.3. Адрес, HAL и WHO_AM_I

В своём коде храни **7-битный** адрес `0x18`. При вызове обычного STM32 HAL F1 передавай `(addr7 << 1)`. Read/write бит формирует HAL. Это не адрес регистра 0x0F и не значение идентификатора 0x33. Правило аргумента `DevAddress` подтверждено [исходником I2C HAL F1](https://github.com/STMicroelectronics/stm32f1xx-hal-driver/blob/master/Src/stm32f1xx_hal_i2c.c).

Прежде чем писать драйвер:

1. Проверь мультиметром idle SDA/SCL: около 3,3 В
2. Один раз вызови `HAL_I2C_IsDeviceReady(&hi2c1, (0x18U << 1), 2U, 20U)`; запиши status и error
3. Прочитай WHO_AM_I, register 0x0F; ожидается 0x33
4. Проверь результат не менее 100 раз, печатая лишь итог и ошибки

Узкий пример чтения одного регистра:

```c
uint8_t who = 0U;
HAL_StatusTypeDef status = HAL_I2C_Mem_Read(
    &hi2c1, (uint16_t)(0x18U << 1), 0x0FU,
    I2C_MEMADD_SIZE_8BIT, &who, 1U, 20U);
if (status == HAL_OK && who == 0x33U) {
    /* Теперь подтверждена конкретная идентификация; пока не измерение. */
} else {
    uint32_t error = HAL_I2C_GetError(&hi2c1);
    /* Сохрани status, error и who для редкого вывода в main. */
    (void)error;
}
```

Общий «сканер всех адресов» не нужен для одного известного устройства. Если исследуешь свою изолированную учебную шину, можно осторожно опросить допустимые обычные адреса 0x08…0x77, но найденный ACK всё равно не доказывает тип устройства. На чужой/рабочей шине не отправляй неизвестные команды.

### 5.4. Получи данные, а не только адрес

Сам найди в даташите CTRL_REG1, CTRL_REG4, STATUS_REG и OUT_X/Y/Z. До записи нарисуй биты. Для конкретного опыта целевые настройки:

- CTRL_REG1 / 0x20: 0x57, 100 Гц, X/Y/Z включены, low-power выключен
- CTRL_REG4 / 0x23: 0x88, BDU, ±2 g, high-resolution, little-endian
- После настройки прочитай эти регистры обратно; дождись установления режима и новых данных через STATUS_REG, с ограничением времени, например 500 мс
- Прочитай шесть байт с 0x28, включив auto-increment в I2C sub-address: 0xA8

Собери signed X/Y/Z из little-endian пар. Данные HR выровнены влево: сначала восстанови signed 16-битное число, затем раздели на 16. Для ±2 g номинальный масштаб — 1 mg/LSB. В переносимом C можно собирать беззнаковую пару в `uint32_t`, затем в `int32_t` вычитать 65536 при установленном бите 15; это не зависит от сдвига отрицательного signed.

**До платы:** декодируй пары `[0x00, 0x40]` и `[0x00, 0xC0]` как low/high. Если обе оси положительные или результат в 16 раз больше ожидаемого, не отлаживай I2C — сначала исправь представление числа.

<details>
<summary>Проверить знак и масштаб</summary>

`0x4000 → 16384 / 16 → +1024 mg`; `0xC000 → (49152 − 65536) / 16 → −1024 mg`. Это синтетические тестовые байты, не обещание показания датчика на столе.

</details>

На неподвижной плате переверни датчик на шесть граней. При оси примерно вертикально широкий ориентир — доминирующая компонента по модулю 0,8…1,2 g, две другие около нуля в пределах 0,2 g. Выход за этот учебный диапазон требует проверить ориентацию, режим, знак и масштаб; это не допуск производителя и не калибровка. Повторный одинаковый sample не обязательно ошибка: сравни частоту чтения с 100 Гц обновления.

### 5.5. Ошибка, которая не вешает устройство

В коде временно поменяй **только** `addr7` с 0x18 на 0x19 при неизменном SA0=GND. Предскажи NACK; не переподключай ничего. Учитывай отдельно HAL status и `HAL_I2C_GetError`: NACK/AF, BUSY, TIMEOUT и BERR требуют разных гипотез.

Ожидается: вызов возвращается, ошибка учитывается, интерфейс пользователя остаётся живым. При NACK останови обычное чтение, сообщи «датчик недоступен» и повторяй редко, например раз в секунду, с ограниченным числом попыток или явной командой пользователя. Не вызывай `Error_Handler()` на каждое штатное отсутствие датчика и не показывай старое число как свежее.

Мини-gate необязательного I2C-маршрута: 100 совпадений WHO_AM_I, верный readback настроек, объяснённые шесть положений и восстановление после опыта с адресом. Без модуля сохраняй «не выполнялось»; SPI-gate от этого не меняется.

Timeout 20 мс в аргументе — не обещание, что любой путь всей операции длится строго меньше 20 мс: в HAL бывают отдельные ожидания BUSY и несколько попыток. Измерь максимальную длительность для своей версии драйвера и используй её в бюджете приложения.

## 6. I2C troubleshooting: сначала измерение, потом workaround

1. **SDA/SCL не high в покое:** питание, земля, подтяжки, неправильный pin mode или устройство держит линию
2. **START есть, адрес NACK:** 7-bit против shifted, SA0, CS, адрес именно твоей микросхемы
3. **ACK есть, WHO_AM_I не совпал:** неверный register/transaction, другое устройство или модуль
4. **Только multi-byte чтение неверно:** auto-increment, порядок байтов, длина, настройка BDU и новая выборка
5. **BUSY при физических high:** запиши уровни, `SR1/SR2`, состояние HAL и ревизию MCU; проверь ES096 §2.8.7

Для последнего пункта обычные `HAL_I2C_DeInit/Init`, software reset и даже reset MCU **не гарантируют** устранение описанной причины. Не вставляй случайную последовательность GPIO из форума. В ограниченном отдельном опыте следуй официальному workaround, с корректным open-drain, проверкой каждого уровня, timeout и возвращением pin mux; либо полностью обесточь безопасную учебную схему и повтори диагностику. Не обещай, что «девять импульсов» исправят любой BUSY. Останови попытки, если линия не отпускается.

## 7. Воспроизведение и незнакомый перенос без AI

**Обязательная часть:** в новой копии самостоятельно собери SPI loopback, выбери другой prescaler и тестовый вектор, заранее предскажи время и полученные байты. Объясни CS, CPOL, CPHA, full duplex и ограничения теста.

**Дополнение:** из даташита другого 3,3-вольтового устройства выпиши питание, адрес/CS, частоту, mode, регистр идентификации и процедуру одного измерения. Сначала сделай read-only идентификацию, затем осмысленное измерение. Не переносить команды LIS3DH по аналогии.

Если переводишь сам LIS3DH с I2C на SPI, сначала полностью обесточь плату, пробник и модуль, затем убери MOSI–MISO loopback, заново нарисуй CS/SCK/SDI/SDO и проверь поддерживаемый режим/командный байт по даташиту. Не оставляй SA0 жёстко на земле, если этот вывод теперь SDO!

AI-подсказка для SPI:

> В моём SPI1 loopback PA7→1 кОм→PA6 получен HAL_OK, но RX не совпал с TX. Вот настройки, вектор, фактический RX и capture, если он есть. Не давай полный драйвер. Сначала проверь, какие гипотезы вообще применимы к этой схеме, затем запроси одно недостающее наблюдение или предложи один безопасный тест. Не объявляй CPHA неверным только по несовпадению байтов: у этого loopback TX и RX используют одну настройку. Отдельно объясни, что ещё понадобится для проверки режима внешнего slave. Перекоммутация только при выключенном питании.

AI-review для I2C:

> Вот схема модуля, ссылка на даташит и мой код. Проверь уровни pull-up, addr7/shift, регистр, timeout, endianness и обработку отсутствия датчика. Не меняй архитектуру за меня; предложи один безопасный тест на каждый найденный риск.
