# L07. ADC: получить число и доказать, что оно означает

**Время:** около 4 часов, тремя подходами по 60–90 минут.  
**Результат:** свой вольтметр для безопасного сигнала 0–3,3 В, таблица ошибок и объяснение влияния источника.  
**До начала:** рабочие сборка, SWD и USART1 из предыдущих лабораторных; умение поставить breakpoint и найти переменную.  
**Минимум для функционального маршрута:** плата, перемычки и резистор 1 кОм. Для измерительного маршрута дополнительно потенциометр 10 кОм и мультиметр; полезны два резистора 10 кОм. Осциллограф необязателен.

> Здесь измеряем только собственную низковольтную схему от 3,3 В платы. Не подключай сеть, автомобильные цепи, зажигание или неизвестный выход. Обозначение «5 V tolerant» на цифровом выводе не разрешает 5 В на аналоговом входе. Земля источника и платы должна быть общей. Переставляй провода при выключенном питании.

## Два честных маршрута

- **A, измерительный:** потенциометр + мультиметр; выполняешь пять уровней и оценку расхождения. Только этот маршрут закрывает проверку напряжения/погрешности.
- **B, функциональный минимум:** без потенциометра и мультиметра. При выключенном питании подключи PA0 через 1 кОм сначала к GND платы, затем в отдельном опыте к её собственной 3V3. Используй только питание платы, проверенное в начальной работе; никаких внешних/неизвестных источников. Запиши по 100 реальных raw-отсчётов на каждом уровне. В отчёте: `voltage_accuracy=unverified`; напряжение в милливольтах не выдаётся за измеренное. Можно продолжать курс, сохранив эту границу проверки.

Не подключай PA0 одновременно к GND и 3V3. Резистор — часть учебной схемы, не универсальная защита.

## 1. Что должен уметь сделать сам

- Отличить номер физического вывода, канал ADC и его rank в последовательности
- Объяснить, откуда берётся шкала 0…4095 и почему она ещё не означает 12 точных бит
- Получить одиночный отсчёт с ограниченным временем ожидания и обработать ошибку
- Сопоставить код ADC с мультиметром, не «подгоняя» данные под 3,300 В
- Обосновать sample time через сопротивление источника и частоту ADC

**Предсказание до включения:** запиши ожидаемый код для GND, середины потенциометра и верхнего вывода. Укажи, какое напряжение ты считаешь опорным и почему.

## 2. Теория на 10 минут

В отличие от привычного `analogRead()`, здесь ты явно выбираешь источник тактирования, канал, время выборки и способ запуска. Sample time — время, когда внутренний конденсатор выборки заряжается от твоего источника. Слишком высокое сопротивление источника вместе с коротким временем выборки даёт ошибку установления; усреднение не исправляет её причину.

Для этой платы принимаем VREF+ равным аналоговому питанию VDDA: проверь фактическую разводку своего варианта Blue Pill. Измерение шины 3V3 мультиметром — практическая оценка VDDA, а не отдельная точная опора.

- Идеальный шаг квантования: `VDDA / 4096`
- Для учебного отображения напряжения по крайним кодам: `U_mV ≈ code × VDDA_mV / 4095`
- Это приближение шкалы. Код 4095 означает насыщение верхней области, а не доказательство точного равенства входа VDDA

Шум, нестабильность опоры, смещение, усиление и нелинейность ограничивают точность. Встроенная калибровка F1 полезна, но не заменяет измерение опоры и не обещает заданный ENOB. Параметры ADC и ограничения источника ищи в разделе ADC characteristics [даташита STM32F103x8/xB](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf).

## 3. Схема и CubeMX

Создай отдельную копию рабочего проекта. В `.ioc` оставь:

| Узел | Настройка |
|---|---|
| MCU | STM32F103C8Tx; Flash 64 КБ, RAM 20 КБ |
| RCC | HSI включён; PLL и HSE не используются |
| SYSCLK / HCLK / PCLK1 / PCLK2 | номинально 8 МГц; делители AHB/APB1/APB2 = /1 |
| ADC clock | PCLK2 /2 = 4 МГц |
| SYS / Debug | Serial Wire; PA13 и PA14 не занимать |
| USART1 | PA9 TX, PA10 RX, 9600, 8N1, без flow control |
| PA0 | ADC1_IN0, Analog; без цифровой подтяжки |
| ADC1 regular | Scan disabled; Continuous disabled; Discontinuous disabled |
| Trigger | Software start |
| Alignment / conversions | Right / 1 |
| Rank 1 | Channel 0; sample time 55.5 cycles |
| DMA и ADC IRQ | пока не включать |

Имена пунктов CubeMX могут отличаться между версиями. Контрольная истина — сгенерированные `MX_ADC1_Init()`, `HAL_ADC_MspInit()` и `SystemClock_Config()`. В HAL F1 ожидаются `ADC_CHANNEL_0`, `ADC_REGULAR_RANK_1`, `ADC_SAMPLETIME_55CYCLES_5`, `ADC_SOFTWARE_START`. Не переносить поля конфигурации ADC из примеров для F4/H7.

Для маршрута A подключи крайние выводы потенциометра к 3V3 и GND, движок через 1 кОм к PA0. Максимальное сопротивление Тевенина потенциометра 10 кОм — примерно 2,5 кОм, плюс твой 1 кОм. Резистор не делает вход защищённым от произвольного напряжения.

Проверь мультиметром GND, шину питания и движок **до** подключения движка к PA0. Альтернатива без потенциометра: делитель `3V3 — 10 кОм — PA0 — 10 кОм — GND`. Напряжение около половины питания зависит от фактических сопротивлений.

## 4. Первый подход: один отсчёт без магии

Сначала напиши функцию самостоятельно по контракту:

`adc_read_once(uint16_t *out)` возвращает `HAL_OK` только если `*out` содержит новый отсчёт. При ошибке старое значение нельзя выдавать как новое. Последовательность: start → poll с timeout → get value → stop. Не использовать `HAL_MAX_DELAY`.

В `USER CODE BEGIN 2`, после `MX_ADC1_Init()`, один раз выполни:

```c
/* STM32F1: калибровка до первого Start. Не вызывать на каждом отсчёте. */
if (HAL_ADCEx_Calibration_Start(&hadc1) != HAL_OK) {
    Error_Handler();
}
```

Это именно однопараметрическая функция F1. Реализация и предусловия есть в [официальном HAL ADCEx](https://github.com/STMicroelectronics/stm32f1xx-hal-driver/blob/master/Src/stm32f1xx_hal_adc_ex.c).

<details>
<summary>Подсказка после собственной попытки: минимальная функция чтения</summary>

В `USER CODE BEGIN 0` или своём `app_adc.c`; для отдельного файла подключи заголовок с `hadc1`.

```c
static HAL_StatusTypeDef adc_read_once(uint16_t *out)
{
    if (out == NULL) {
        return HAL_ERROR;
    }
    HAL_StatusTypeDef status = HAL_ADC_Start(&hadc1);
    if (status != HAL_OK) {
        return status;
    }

    status = HAL_ADC_PollForConversion(&hadc1, 10U);
    uint16_t value = 0U;
    if (status == HAL_OK) {
        value = (uint16_t)HAL_ADC_GetValue(&hadc1);
    }
    HAL_StatusTypeDef stopped = HAL_ADC_Stop(&hadc1);
    if (status == HAL_OK && stopped == HAL_OK) {
        *out = value;
        return HAL_OK;
    }
    return status != HAL_OK ? status : stopped;
}
```

</details>

В главном цикле выполняй чтение примерно раз в 100 мс. При 9600 8N1 держи строку не длиннее 40 байт: это до 400 байт/с из теоретических 960 байт/с. Пока допустим `HAL_Delay(100)`: это проверка одиночного измерения, а не стабильная дискретизация. Публикуй raw-код, номер успешного измерения, оценку милливольт и счётчик ошибок. Счётчик успешных измерений не увеличивается при ошибке.

Для целочисленного округления используй 32-битное произведение:

```c
uint32_t mv = ((uint32_t)raw * vdda_mv + 2047U) / 4095U;
```

`vdda_mv` — записанное измерение питания, не автоматически известные 3300. Форматирование и UART оставь в `main`, не в обработчике прерывания.

**Контрольная точка 60–90 минут:** проект пересоздаётся из `.ioc`; PA0 не настроен выходом; GND даёт нижнюю часть шкалы, движок меняет код монотонно в целом; ты можешь показать каждый шаг получения одного отсчёта в отладчике.

## 5. Второй подход: измерить ограничения

Этот раздел полностью выполняется в маршруте A. В маршруте B сохрани raw для двух уровней, расчёт времени преобразования и объяснение неопределённой опоры; таблица точности и влияние сопротивления остаются не проверенными, а не автоматически зачтёнными.

1. Сними для пяти положений потенциометра: `U_DMM`, измеренное питание, средний raw за 100 отсчётов, min, max и оценку `U_ADC`. Крайние точки не используй для доказательства линейности: там возможна насыщенность.
2. Рассчитай абсолютное расхождение `U_ADC − U_DMM`. Укажи разрешение/точность мультиметра, если они известны. Не называй его абсолютной истиной без допуска.
3. Рассчитай время преобразования при выбранных часах: `(55,5 + 12,5) / 4 МГц = 17 мкс`, без учёта задержки запуска и затрат HAL. Это **не** период твоего цикла с UART и `HAL_Delay`.
4. Не двигая потенциометр, сравни min/max и среднее одиночных значений и блоков из 16. Укажи дополнительную задержку усреднения. Меньший разброс среднего не доказывает больше полезных бит или исправление смещения.
5. Найди в даташите формулу/таблицу допустимого сопротивления источника. Сравни свой максимум около 3,5 кОм с выбранными временем выборки и частотой. Не бери значение из таблицы для 14 МГц как готовое значение для 4 МГц без проверки условий.

Никакой фильтр ещё не является антиалиасинговой защитой. При измерении переменного сигнала частоту дискретизации и аналоговую полосу нужно выбирать совместно; это вернётся в следующей работе.

## 6. Безопасная намеренная поломка

**Основная:** в копии проекта ошибочно выбери ADC channel 1, сохранив провод на PA0. PA1 в этой копии переведи в аналоговый вход, убедись, что PWM выключен. Не меняй провода под питанием. Предскажи результат, затем проверь.

Признак: исправный HAL может возвращать меняющиеся, но не связанные с движком числа. `HAL_OK` подтверждает завершение операции, а не правильный физический источник. Восстанови channel 0 и покажи причинное исправление.

**Дополнительно:** замени потенциометр делителем из двух 100 кОм и сравни самое короткое/длинное sample time. Эффект может быть небольшим при медленном одиночном опросе одного канала, потому что внутренний конденсатор уже близок к тому же напряжению. Честно зафиксируй «различие не обнаружено», а не придумывай ошибку. Для уверенного исследования потребуется смена уровней/каналов и учёт динамики источника.

Не делай учебную «поломку» подачей 5 В или переполюсовкой.

## 7. Если не работает

- **Всегда около нуля:** сначала измерь напряжение прямо PA0–GND; проверь обрыв движка, канал и Analog mode
- **Всегда около 4095:** проверь вход и землю; если вход выше VDDA, немедленно выключи питание и исправь схему
- **Timeout:** посмотри RCC ADC clock, `hadc1.Instance`, результат start и сгенерированную инициализацию
- **Код меняется, вольты странные:** проверь `vdda_mv`, 32-битное умножение и порядок целочисленного деления
- **Результат меняется после касания:** возможны плавающий вход, плохой контакт или высокая импедансность; касание не является измерительным методом
- **UART портит частоту:** отдельно измеряй время ADC и время передачи, не оценивай скорость ADC по строкам терминала

## 8. Критерий готовности и доказательства

Сохрани `.ioc`, свой код, фото безопасной схемы и короткий `evidence/L07.md`:

- Пять измеренных уровней, исходные raw и расчёт расхождения
- 100 отсчётов неподвижного источника: min/max/mean и счётчик ошибок
- Расчёт ADC clock, времени преобразования и сопротивления источника
- Ошибочный канал: гипотеза → наблюдение → исправление
- Три честных ограничения твоего «вольтметра»

Для маршрута B gate — две серии по 100 raw, нижний уровень рядом с нижней частью шкалы и верхний рядом с верхней, отсутствие ошибок HAL, верно выбранный канал и воспроизводимость после reset. Никакой точности в вольтах этот gate не подтверждает. Если нельзя проверить безопасность питания, сначала вернись к начальной настройке.

Учебный ориентир маршрута A: при устойчивом подключении средний raw для около половины питания должен быть близок к середине шкалы; если расхождение с мультиметром больше 2% полной шкалы, найди причину. Этот широкий диагностический порог — не спецификация точности STM32 и не обещание результата каждой платы.

## 9. Воспроизведение и перенос без AI

Закрой эту страницу и предыдущий проект. За 30–45 минут восстанови одиночное чтение PA0 с timeout и обработкой ошибок, пользуясь только CubeMX и первичной документацией. Объясни calibration, rank, sample time и отличие 4095 от 4096.

**Незнакомая задача:** измерять переменный резистор как долю собственного питания, без выдачи ложных «точных вольт». Сам выбери формат результата, обоснуй, какие ошибки стали менее существенны и какие остались. Затем перепиши этот контракт как функцию на чистом C и проверь крайние значения.

AI-подсказка, только после своей попытки:

> Вот моя схема, параметры ADC, пять измерений и гипотеза. Не пиши готовую лабораторную. Сначала найди одно противоречие и задай один проверочный вопрос. Если оно есть, предложи один эксперимент, различающий две причины. Проверь API именно STM32F1 по официальному источнику.

Для review:

> Проверь мой diff на неверный канал, потерянные USER CODE, бесконечные ожидания, переполнение арифметики и выдачу старого значения как нового. Не переписывай решение целиком. Приведи риск, строку и проверку.
