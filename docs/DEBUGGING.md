# Отладка: найти сломанный этап

Сначала определите, что уже доказано. «Светится LED питания» подтверждает далеко не всё. «В терминале нет ошибок» тоже не доказывает, что запущен новый образ.

## За минуту: выбрать следующий тест

Сначала ответьте себе на один вопрос: **какой последний этап подтверждён файлом, логом или наблюдением?** Затем идите только на один шаг вперёд:

1. **Нет свежего `.elf`** → проверять Generate/Configure/Build. Плата и BOOT0 пока не участвуют.
2. **`.elf` есть, probe не виден** → USB-кабель, драйвер/права, занятая сессия. Не менять HAL-код.
3. **Probe виден, target нет** → питание и SWD, затем ограниченный Under Reset.
4. **Target читается, verify неуспешен** → выбранный образ/память/лог записи. Не считать старое мигание успехом.
5. **Verify прошёл, поведение неверно** → тот же `.elf` в debug; breakpoint в `main`, затем Resume и RESET.

Перед чтением строки таблицы выберите **одну** гипотезу и наблюдение, которое её опровергнет. Если уже пробовали безопасный тест, сохраните результат вместо повторения случайных установок.

## Короткий маршрут диагностики

| Симптом | Первая проверка | Следующий ограниченный эксперимент |
|---|---|---|
| CubeMX не предлагает STM32F103 | Выбран ли исходный CubeMX, установлен ли STM32CubeF1 | Проверить точную маркировку и список MCU |
| Нет CMake | Версия/режим генератора | Обновление с копией `.ioc` либо отдельный Makefile-маршрут |
| Compiler not found | Что запускается в build-логе | Проверить окружение ST, затем `arm-none-eabi-gcc --version` |
| Configure прошёл, Build упал | Первая содержательная ошибка, не последняя строка | Исправить один missing include/source/symbol и повторить |
| Новый `.c` есть, но undefined reference | Попал ли он в список компиляции; совпадает ли имя/прототип | Проверить пользовательский список sources и build-лог |
| После смены GCC собирается старой цепочкой | Компилятор и каталог configure cache | После выбора правильного toolchain пересоздать только build-каталог; исходники и `.ioc` сохранить |
| Переполнение Flash | Выбран ли C8, что показывает `.map` | Найти крупные объекты; не выдавать C8 за CB |
| Пробник не виден компьютеру | USB data-кабель, разъём, драйвер, доступ USB | Проверить без платы: определяется ли сам пробник |
| Пробник виден, target не виден | Питание, GND, SWDIO/SWCLK, VTref, NRST | Уменьшить SWD-частоту; затем Connect Under Reset |
| Запись прошла, LED не меняется | Тот ли `.elf`, был ли verify, не остановлен ли CPU | Breakpoint в `main`, затем Resume и RESET |
| Breakpoint серый/не достигается | Совпадают ли исходник и ELF, есть ли debug symbols, выполняется ли этот код | Пересобрать Debug; первым ставить breakpoint в `main` |
| Watch показывает 0 на строке `++` | Строка уже выполнена или остановлена перед ней? | Один Step Over и повторное чтение; ожидается 1 |
| Под USB платы не появляется COM | Есть ли вообще USB CDC в прошивке | Использовать UART-переходник/VCP; L00 не создаёт USB-устройство |
| Работает только в debug | BOOT0, reset, образ во Flash, зависимость от debugger | Завершить сессию и проверить самостоятельный старт |
| Частота отличается ровно вдвое | APB divider и TIM clock | Пересчитать из [дерева частот](TOOLCHAIN.md#clocks) |
| UART выдаёт мусор | TX/RX, GND, 3,3 В, baud, parity, clock | Короткая строка на 9600 8N1; проверить частоту и делитель |
| После Generate исчез код | Где находились изменения | Сравнить Git diff; восстановить пользовательские области |

## 1. Не спутать проблему ПК и проблему платы

Отсоединённый target не должен мешать ОС обнаружить USB-пробник. Если пробника нет, ещё рано менять BOOT0 или HAL-код. Проверьте data-кабель: зарядный кабель может питать устройство без передачи данных. Уберите сомнительный hub и длинные удлинители.

Если ОС видит пробник, но приложение не открывает его, закройте другие debug/programmer-процессы. На Windows проверьте официальный драйвер, на Linux — предусмотренные пакетом права USB/udev. Не используйте случайную замену драйвера как универсальный рецепт.

Firmware пробника обновляйте официальным средством для **подтверждённой модели**, когда это требуется совместимостью. Не прошивайте неизвестный адаптер «как оригинальный ST-LINK» только потому, что корпус похож.

## 2. МК не отвечает по SWD

1. Отключите питание, внешние устройства и лишние провода.
2. Сверьте соединения с [SAFETY](SAFETY.md). Не доверяйте порядку контактов на фотографии другого пробника.
3. Подайте питание единственным выбранным способом; измерьте шину 3,3 В.
4. Выберите SWD, низкую доступную частоту, обычное соединение.
5. Если прошивка успевает отключить SWD/уйти в мешающий режим, соедините NRST и выберите **Connect Under Reset**. Аппаратный reset требует физического NRST. [CubeProgrammer: connect modes](SOURCES.md#s13).

Читаемая маркировка, лог ID/Flash и схема платы полезнее догадок. Не исправляйте «Unexpected ID» отключением проверки идентификатора или подменой размера памяти. Причиной может оказаться другой кристалл, проводка, питание или несовместимый пробник. Это ещё не доказательство, что МК поддельный или сгорел.

## 3. Восстановление после неудачного учебного кода

Сначала попробуйте Connect Under Reset с NRST и запись ранее работавшего минимального HSI-проекта. Не стирайте всю память как первый шаг.

Если обычный запуск пользовательской программы мешает связи, можно при **отключённом питании** выставить `BOOT0=1`, `BOOT1/PB2=0`, включить питание/сделать reset и снова подключиться. Это выбирает системную память, а не вашу программу. После восстановления верните `BOOT0=0`, затем reset. При `BOOT0=1` и `BOOT1=1` выбирается SRAM, что не является нужным загрузчиком. Таблица выбора: [AN2586, §4](SOURCES.md#s3).

**Не экспериментируйте с Option Bytes, readout protection, write protection и командами unprotect в этом курсе.** Снятие защиты и полное стирание могут уничтожить содержимое Flash. Если плата содержит нужную чужую/старую прошивку, остановитесь до записи или стирания и разберитесь с возможностью резервной копии.

## 4. Если есть USB–UART, но пока нет SWD

Эта ветка относится к настоящим **STM32F103x8/xB**, а не ко всем МК с похожим названием.

AN2606, раздел **STM32F10xxx devices**, описывает ROM-загрузчик USART1: PA10 — приём, PA9 — передача, формат 8 бит данных с even parity и одним stop bit. Он использует внутреннее тактирование. USB DFU для этой группы в ROM не предусмотрен. Не переносите описание F105/F107 на F103C8. [AN2606, Rev 70, §21, таблица 45](SOURCES.md#s4).

Порядок:

1. Подготовьте USB–UART с проверенным **TX уровня 3,3 В**, не RS-232. Отключите терминал: COM-порт должен быть свободен.
2. При отключённом питании: TX переходника → PA10; RX → PA9; GND → GND. Плату питайте единственным уже проверенным способом; питание переходника не подключайте автоматически.
3. Установите `BOOT0=1`, `BOOT1/PB2=0`; подайте питание и сделайте RESET.
4. В CubeProgrammer выберите UART и фактический порт, начните с умеренной скорости, например 9600; формат загрузчика — **8E1**, без аппаратного flow control. Подключитесь.
5. Запишите образ с verify. Для `.bin` стандартного проекта курса используйте `0x08000000`; для адресного формата следуйте его карте памяти.
6. Отключите питание, верните `BOOT0=0`, включите/сбросьте плату и проверьте автономный запуск.

Ограничения: здесь нет breakpoint, пошагового выполнения и просмотра регистров. Это не замена SWD для отладочных задач L00/L01. Наличие пользовательского USB-bootloader на конкретной плате — отдельный факт, который надо установить; его адресное смещение нельзя предполагать. Ошибка UART-связи также не доказывает отсутствие ROM: сначала проверяются BOOT, уровни, общий GND и перекрёстное TX/RX.

## 5. Минимальная полезная debug-сессия

1. Соберите `Debug` с символами. Используйте один свежий `.elf` для кода, символов и загрузки.
2. Остановитесь в `main`, затем пройдите инициализацию до пользовательского кода. Если попали в `Error_Handler`, посмотрите, какой вызов HAL вернул ошибку.
3. Поставьте breakpoint на изменение счётчика. Проверьте глобальную переменную в Watch и значение PC.
4. Продолжите выполнение. Затем Pause: где находится ядро и меняется ли ожидаемое состояние?
5. Завершите сессию и проверьте RESET без debugger.

В учебном счётчике `volatile` помогает сохранить реальные чтения/записи для наблюдения. Это не универсальное средство синхронизации и не гарантия атомарности составных операций. Оптимизация может удалить переменную или переставить инструкции; «optimized out» не обязательно ошибка программатора.

`HAL_Delay` зависит от системного tick. Когда CPU остановлен на breakpoint, обычное время выполнения программы не идёт так, как при свободном запуске. Не измеряйте период программы секундомером во время single-step. Аппаратные таймеры и watchdog имеют собственные правила остановки при debug; их freeze-настройки рассматриваются в профильных лабораториях.

Страница ST [Debug](SOURCES.md#s11) описывает возможности и текущий запуск. GDB server оставляйте доступным только локально: он не предназначен для открытого доступа из недоверенной сети.

## 6. Частные ловушки Blue Pill

- **Индикатор питания и пользовательский LED — разные вещи.** Проверяйте вывод и полярность.
- **Не запускается HSE:** вернитесь к сохранённому HSI-проекту. Не меняйте одновременно PLL, задержки Flash и UART.
- **На корпусе C8, инструмент показывает 128K:** курс продолжает использовать гарантированные 64K. Неофициальная доступность дополнительной области не делает её спецификацией C8.
- **Есть 5 В, нет правильных 3,3 В:** сначала цепь питания/стабилизатор, потом программирование.
- **USB-разъём есть, USB-функции нет:** подключение и firmware должны действительно реализовывать нужный USB-класс. Первый успех по SWD не зависит от USB-периферии МК.
- **Пропала связь после нового GPIO-кода:** проверьте, что сохранён Serial Wire и не заняты PA13/PA14.

## 7. Журнал вместо случайных исправлений

На каждую проблему запишите:

```text
Последний доказанно рабочий этап:
Точная первая ошибка / лог:
Ожидание:
Одна гипотеза:
Одно безопасное изменение:
Наблюдение после изменения:
Вернуть изменение или оставить, и почему:
```

Для запроса помощи достаточно маркировки МК, модели пробника, способа питания, схемы соединений, `.ioc`, версий и полного первого error-блока. Не прикладывайте только последнюю строку `build failed`.
